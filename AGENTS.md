AGENTS.md — Agent Guidelines for ztdns

Build & Run
- Build binary: `go build ./...`
- Build Docker image: `docker build -t ztdns .`
- Run locally with Docker Compose: `docker-compose up --build`

Test
- Run all tests: `go test ./...`
- Run a single package: `go test ./ztapi -v`
- Run a single test by name (regex): `go test ./ztapi -run '^TestMember$' -v`

Lint & Format
- Format code: `gofmt -s -w .`
- Fix imports: `go install golang.org/x/tools/cmd/goimports@latest && goimports -w .`
- Static checks: `go vet ./...`
- Optional linter: `golangci-lint run` (if installed)

Code Style Guidelines
- Formatting: always run `gofmt`/`goimports` before committing.
- Imports: group as standard, third-party, internal; separate groups with a blank line.
- Naming: exported identifiers `PascalCase`; unexported `camelCase`; use short loop vars `i, j` only for small loops.
- Types: prefer concrete types; accept interfaces for dependencies only when useful.
- Error handling: return errors; avoid `panic` in library code; wrap errors with `fmt.Errorf("%s: %w", msg, err)`.
- Logging: use the standard `log` package or project convention; do not log secrets.
- Tests: use table-driven tests and `t.Run` for subtests; keep tests deterministic.
