**AGENTS.md — Agent Guidelines for ztdns

**Build & Run**
- Build binary: `go build ./...`
- Build Docker image: `docker build -t ztdns .`
- Run with Docker Compose: `docker-compose up --build`

**Test**
- Run all tests: `go test ./...`
- Run a single package: `go test ./ztapi -v`
- Run a single test by name (regex): `go test ./ztapi -run '^TestMember$' -v`

**Lint & Format**
- Format: `gofmt -s -w .` (or `gofmt` via editor)
- Imports: `go install golang.org/x/tools/cmd/goimports@latest` then `goimports -w .`
- Vet: `go vet ./...`
- Recommended: `golangci-lint run` (if installed)

**Code Style Guidelines**
- Formatting: Always run `gofmt`/`goimports` before committing.
- Imports: group as standard, external, internal (blank lines between groups).
- Naming: exported identifiers `PascalCase`; unexported `camelCase`; short loop vars `i,j` only in small scopes.
- Types: prefer concrete types for clarity; accept interfaces for dependencies only when useful.
- Errors: return errors; do not `panic` in library code; wrap/contextualize errors with `fmt.Errorf("...: %w", err)`.
- Logging: use the standard `log` package or project logging convention; avoid leaking secrets.
- Tests: use table-driven tests and `t.Run` for subtests; keep tests deterministic.

**Generated Files**
- If a file starts with `// Code generated by go-swagger; DO NOT EDIT.` treat it as read-only and do not modify it.

**Cursor / Copilot rules**
- No `.cursor` or `.cursorrules` found in repo; no `.github/copilot-instructions.md` present.

Keep changes minimal and focused; if unsure, ask for guidance before modifying public APIs.
